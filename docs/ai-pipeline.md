# AI & Speech Pipeline

## Workflow Overview
The intelligence pipeline is designed to be "Transcript-First." All analysis originates from a text transcript, which is either supplied directly or generated from audio.

### 1. Audio Processing & Speech-to-Text
When a meeting concludes or an audio file is uploaded:
- The file is saved in the `uploads/` directory.
- The `ProcessingService` initiates the `WhisperSpeechToTextService`.
- Using the `openai` SDK (`whisper-1` model), the audio is transcribed.
- The resulting text is saved to a `Transcript` database record.

### 2. AI Intelligence Extraction
Once a transcript is available, the `AIService` (backed by `OpenAIService`) takes over:
- It uses a strict JSON schema and system prompt to analyze the transcript.
- **Summary**: Condenses the meeting into a brief overview.
- **Key Points**: Highlights main topics discussed.
- **Decisions**: Extracts formalized agreements and their contexts.
- **Action Items**: Identifies tasks, potential assignees, deadlines, priorities, and confidence scores.

### 3. Human Review Process
- Action items generated by AI are stored as `Task` records with `status = "PENDING_REVIEW"` and `source = "AI"`.
- Employees **cannot** see these tasks.
- A Manager or Admin must review the tasks via their dashboard.
- The Manager can Confirm, Edit, Reassign, or Reject the task.
- Once confirmed, the status changes to an actionable state (e.g., `PENDING` or `IN_PROGRESS`), at which point the Employee is notified and sees the task.

## Provider Abstraction
The system supports swappable providers for both Speech and AI:
- **Speech**: `WhisperSpeechToTextService` (Real), `MockSpeechToTextService` (Fallback/Testing).
- **AI**: `OpenAIService` (Real), `AnthropicService` (Optional alternate), `MockAIService` (Fallback/Testing).
